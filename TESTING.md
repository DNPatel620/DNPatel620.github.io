# Website Test Plan

## Test setup and current scope

Run the browser tests against the local site (for example, open `index.html` in a browser). Use a phone-sized viewport of **390 × 844 px** and a laptop viewport of **1366 × 768 px**. For Lighthouse tests, open Chrome DevTools, select **Lighthouse**, run an **Accessibility** audit, and record the score.

The intended site pages are `index.html`, `about.html`, `projects.html`, `skills.html`, and `contact.html`. The shared shell and all five pages are present. Step 4 adds a responsive navigation toggle and a client-side contact form. On 2026-10-26, static checks confirmed that each page has exactly one `<h1>`, working `style.css` and `script.js` references, no missing local links or image paths, and alt text on every image. CSS braces are balanced, and all three project illustrations are under 500 KB. Source checks also confirmed that contact fields have labels and required validation, the email field uses email input validation, the form is hidden without JavaScript, its handler prevents submission, and no network or storage APIs are used. The local browser inspection could not proceed because the computer-use layer stopped on an unsupported URL-policy check. Rendered viewport, keyboard/form interaction, JavaScript execution, and Lighthouse results therefore remain unverified.
